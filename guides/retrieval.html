Retrievable tables

Some tables list rows that came from somewhere else — a marketplace’s orders, a feed’s entries — and a reader wants them fetched again. This guide is the keyword that says so, what it draws, and the one controller the host writes.

Chapters
  1. The keyword
  2. The controller
  3. Saying there is nothing to fetch from

The keyword

recourses :stores do
  recourses :orders, only: :index, retrievable: true
end

That draws POST /stores/5/orders/retrieval, named store_orders_retrieval, and puts a Retrieve button on the table that lists them, beside the breadcrumb. The button is labelled for a screen reader with the rows it fetches: Retrieve orders again.

The keyword is refused on a resource with no index, since the button stands on the table that lists the rows and there would be nowhere to put it.

The controller

Where the rows come from is the host’s to know, so the controller is the host’s to write, and the gem makes one only where there is none — the same bargain a bare action strikes. It is named after the resource, under the parent, and it is a RecoursesController like every other screen, so the same guard stands above it:

class Stores::Orders::RetrievalsController < RecoursesController
  def create
    store = Store.find params.expect(:store_id)
    store.import_orders
    flash.notice = 'Fetching orders'
    redirect_to store_orders_path(store), status: :see_other
  end
end

The work belongs to the model, or to a job the model enqueues, and the action says it started. A redirect after a non-GET carries status: :see_other, since every screen is a Turbo visit.

Saying there is nothing to fetch from

An index of a marketplace’s orders is no use to a store that has connected none, and only the host knows it. The listing controller answers recourse_retrievable?, true unless narrowed, and the button is drawn only where it holds:

class Stores::OrdersController < RecoursesController
private

  def recourse_retrievable? = @store.connected?
end

Private, so narrowing it adds no action. The route stays drawn either way; it is the button that goes.
