Models

Most models need to say nothing: the screens read the validators, the associations, the column types and the indexes. This guide is the class methods a model may answer when the default is not what it wants, and then everything the schema already decides.

The hooks

Every Active Record model answers these; a model overrides one as a class method.

HookDefaultDecides
recourse_label:namethe column a combobox shows and a foreign-key cell reads; typed rather than picked where it has a length validator
recourse_hidden[]columns kept off the table, the page, the form and the search
recourse_order:id, or the positioned columnthe index’s order, a Symbol or a Hash; rows with nothing in the column come last
recourse_position'position' where the model keeps an integer onethe column a reader drags the rows into order by, or nil for a table nobody positions

recourse_iconthe model’s namethe icon on the sidebar, the crumbs and the tabs
recourse_includesevery belongs_towhat the index eager-loads, in any shape includes takes

recourse_broadcasts?truewhether saving a record redraws every open index listing it

A model with more than a line of these keeps them in a concern of its own, so the model body stays the model’s:

# app/models/post/recoursive.rb
class Post
  module Recoursive
    extend ActiveSupport::Concern

    class_methods do
      def recourse_label = :title
      def recourse_hidden = :ip_address
      def recourse_order = { published_at: :desc }
      def recourse_icon = :question
    end
  end
end

The label

recourse_label is the column one record is known by: what a combobox lists, what a foreign-key cell in another table reads, what a toast calls the record it wrote, and what the breadcrumb over a nested page says. It has to be a real column, since the combobox selects only the id and the label.

Where that column has a length validator the label is short enough to type, so a form asks for the value — Country code — rather than listing every record, and the value is looked up on the way in: a code naming no record leaves the key nil and Must exist beside the field. The same happens where the other table is too long to list, which is 200 rows.

An encrypted label is drawn in the clear wherever a label is drawn, tables of other models included. That is a decision to make deliberately rather than fall into.

Hidden columns

recourse_hidden takes a column off every screen at once: the table, the record’s page, the form, the search box, the sort headings and the filter menus. It has no table-only form — a column that is only noisy on an index stays, or gets a _row partial of the host’s own. One name or a list: def recourse_hidden = :name reads as well as %i[name title]. It also keeps an attachment off every screen: recourse_hidden :photos.

A column a form needs is a column no model should hide. The columns a form offers are the columns it permits, so hiding one the database requires with no default leaves a form that cannot save.

Order, icon and includes

recourse_order is any shape order takes. A Symbol or a Hash also puts the rows with nothing in the column last, whichever direction is asked; a SQL string is taken as written. A positioned model is ordered by its position column, since the order a table is read in and the order somebody put it in are one fact.

recourse_icon names a concept rather than an icon — :question, not question-circle — and unicon says what that concept is called in Bootstrap Icons. The default is the model’s own name, so a User draws what unicon draws for a user without saying so, and a name unicon has never heard of draws nothing rather than a placeholder.

recourse_includes is what the index eager-loads: every belongs_to by default, so twenty comments naming an author cost one query for the authors rather than twenty. A host whose row reads through a second key names it as a hash, the shape includes already takes — [:author, { post: :category }] — and the table’s cache key follows it there, so a change to any record the rows draw expires the table.

Counters

A number is drawn as a count — headed with the icon of what it counts, linking to the rows behind it — when its column holds a counter cache, or is named <association>_count for an association the model has. So a figure the app keeps itself needs nothing declared:

class Author < ApplicationRecord
  has_many :comments, through: :posts   # and a comments_count column beside it
end

The rule a host signs up for: a *_count column whose prefix names an association must hold the count of that association. One naming nothing — word_count, retry_count — is an ordinary number, and one naming an association it does not count wants another name or a place in recourse_hidden, since the heading and the link would both say the wrong thing.

A counter links to the nested index of those rows where the routes drew one under the record. The tab on the record’s card reads the same count.

Money and a percentage are told apart from other decimals by their type — an Active Record type reporting :monetary or :percentage, declared with attribute — never by their name, so price is money and discount_rate a share of it.

Encrypted columns

Active Record Encryption is respected throughout. An encrypted column never reaches a table, since a page of twenty rows is what a screenshot discloses; it arrives masked on the record’s own page — one asterisk per character and a Show beside it — and it is offered in the clear on the form that edits it, editing one record being already a deliberate act.

A search matches an encrypted column whole, never by containment, and only where the encryption is deterministic: a LIKE against ciphertext finds nothing, and non-deterministic ciphertext differs every write. A model whose searchable columns are all encrypted gets a box that asks for an exact value.

Attachments

A has_one_attached :avatar is a file field on the form and, on the record’s page, the picture Active Storage makes of the file — 100 pixels tall, WebP where the browser takes it, opening the whole file in a new tab — or the file’s name where nothing can be drawn of it. Under the field on an edit form, a line says what the record is holding now.

A has_many_attached :photos earns a page of its own once it is routed under the record:

recourses :posts do
  recourses :photos, only: %i[index destroy]
end

That page is a table of the files with their pictures, and a Delete on each row that takes the file off the record. Files are added on the record’s own form, where a chosen file joins a shelf and replaces a single one, and a field nobody touched leaves everything as it was. Drawing a picture of an image needs image_processing; video and PDF also need the host’s ffmpeg and poppler.

Column comments

Where the database has said what a column is for, the form says so under its field. recourse_comment reads the schema’s comment, which is the one question about a column no validator can answer. An adapter that keeps no comments — SQLite is one — answers nil, and a host on it answers by hand:

COMMENTS = { 'quantity' => 'How many are in stock' }.freeze

def self.recourse_comment(column) = COMMENTS[column] || super

Search, sort and filters

The Ransack hooks default to something rather than to nothing, so a model that says nothing is fully searchable, sortable and filterable. The search box looks through every indexed string column the table shows, plus the label behind a foreign key too long to list; a heading sorts where an index covers the column, and on every counter and timestamp, never on a foreign key; and a filter is drawn per enum, per boolean and per foreign key whose table is short enough to list.

ransackable_attributes, ransackable_associations, ransortable_attributes and filter_fields are still the model’s to override, and each narrows what is offered with it: a column Ransack will not answer for is offered no filter.

filter_fields is a list of predicates and nothing else. A model adds a menu the schema says nothing about — a word reached through another table — by naming the predicate, and the gem reads the words off the model behind it and heads the menu as the locale calls that model:

def self.filter_fields = super + %i[category_name_in]
def self.ransackable_associations(_ = nil) = super + %w[category]

Naming a filter is not leave to query through a table, so ransackable_associations still says how far Ransack may reach. A predicate Ransack will not answer raises when the page draws, rather than drawing a menu that narrows nothing and hands back every row.

Wording a deletion

Deleting is not what every model does when a row goes: a subscription is canceled, a note is withdrawn. Both the button and the heading over the dialog read the model’s own words where a host wrote them in the locale, keyed off the record’s own class so a subclass words it apart from its siblings:

en:
  recourse:
    models:
      subscription:
        delete: Cancel %{model}
        deletion_title: Cancel %{record}?

The rest of the dialog — what goes with the record, what is kept, This cannot be undone. — is the gem’s, and is in Records and forms.

Broadcasts

When the host runs turbo-rails, saving a record redraws every open index listing it, morphed in place with the scroll and the search box kept. A model written far more often than it is read quiets its own:

def self.recourse_broadcasts? = false
