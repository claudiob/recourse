Tables

The table every index draws: which columns it shows and in what order, how it is sorted, searched and filtered, how it is paged, and what else a row can carry.

Which columns, in which order

A table draws one column per attribute the model has, less four kinds it leaves off by default: encrypted columns, the primary key, the two timestamps, and JSON. recourse_hidden takes any other column off; see Models. A position column is never drawn, since the row’s own place in the table already says it.

The order is banded, and the schema’s own order stands inside each band: an enum first, then foreign keys, then scalars, booleans, long values, dates, timestamps, and counters last of all. A state is read first, what a row points at next, what it counts after everything the row is. There is no hook for the order across bands; a column-reorder migration moves one within its band, and a host _row partial draws any order at all.

Column headings come from human_attribute_name, so a host renames one by translating the attribute. A date or a time is headed without the at or on its column ends in: Created, not Created at.

The action columns

A table opens with one narrow column per action a row has: an eye linking to the record’s page and a pencil to its form, each drawn only where its action is routed. A look before a change, so the pencil is not the first thing under the cursor. A resource with neither opens at its first attribute.

A resource routed destroy with no edit has no page to carry the Delete button — a file attached to a record, a row joining two — so its table draws a third column: the trash icon, with the same dialog the record’s page would have shown. A table whose rows have an edit page draws no delete on the row: a row of pencils with a bin beside each is a mis-click waiting to happen.

Where a host writes its own _row partial these columns are still prepended, since they are the table’s rather than the row’s.

How a cell reads

A cell reads as what its column is of, the way the record’s page does: a foreign key as the label of the record it points at, linked to that record’s page where one is routed; a boolean as Yes or No; an enum as a badge; a number delimited; a date by its name and a time in the reader’s zone with how long ago in a tooltip; a web address as its host, with an arrow that opens it in a new tab; a phone punctuated; a list as 3 items. The full table is in Models.

A counter reads as the figure alone under an icon heading, and as 1,204 comments under a word once the table is wide enough. Each is a link to the rows it counts where a nested index of them is routed under the record.

Sorting

A heading is a link where its column can be sorted: the timestamps, every counter, and whatever an index covers. Never a foreign key — its cell shows a label from another table, and the id under it is not the order that label reads in — and never a hidden column. The first click sorts downward, since the newest, the most and the latest are what a reader clicks a heading to find, and the second turns it back up. Rows with nothing in the sorted column come last either way. Clicking a heading restarts at the first page and keeps whatever search or filter was in force.

The model’s own order, before anyone clicks, is recourse_order: the id, or the position column on a positioned table.

Searching

The search box looks through every indexed string column the table shows, plus the label behind each foreign key whose table is too long to list — /orders searches customer_name_cont — and says so in its own placeholder: Filter by title or slug. Typing submits after a moment of quiet, and only the table is replaced, so the caret stays where it was. What the search matched is marked in the cell that matched it, and only there; a search never looks through a number.

A model whose searchable columns are all encrypted gets a box asking for a whole value — Filter by exact email — and only deterministic encryption qualifies. A model with nothing worth searching and no filters gets no form at all.

Filters

Beside the box, one menu per enum, per boolean and per foreign key whose table is short enough to list. Each is a combobox with a search box of its own, ticking more than one value, and opening with All statuses as the way back to no filter. Where the model a menu lists counts the rows being filtered, each option ends with its count and the menu is ordered by it; a page under a record shows no counts, since the number would be of a table the page is not showing. Ticking an option answers at once.

A foreign key too long to list — 200 rows — gets no menu, and a place in the search box instead, so a page never loses the ability to narrow by it. A model adds a menu of its own by naming the predicate in filter_fields; see Models.

Pages

A table opens at 15 rows, and the footer offers 100 per page for a reader scanning rather than reading. The choice is the reader’s, kept in their browser as a cookie and checked against those two sizes, so no page carries a ?limit= and nothing is written to the host. Under the table: Displaying items 1-15 of 101, the switch, and the pages at the right; a table that fits on one page says how many items it has and offers neither.

Bookmarks

One line in an initializer names the viewer’s kept rows, as a Proc, because at boot the viewer is nobody:

Recourse.bookmarks = -> { Bookmark.where user: Current.user }

Every model with a has_many at that class then opens its table with a square to keep a row by, ahead of the action columns: hollow where the viewer has not kept the row, filled where they have, the row tinted with it. Kept rows come first. A click flips the square at once, posts in the background, and the tint follows the write back; a bookmark asks nothing first, since a mis-click is undone by clicking again. A model that cannot hold a bookmark gets no column, and a nested listing keeps its rows at the resource’s own route rather than under every parent.

Live refreshes

When the host runs turbo-rails, an open index subscribes to its model’s refreshes: a record saved in one browser redraws the table in every other one that has the page open, morphed in place, with the scroll, the search box and any open menu kept. A refresh re-fetches the current address, so the search, the sort and the page survive it. A model opts out with recourse_broadcasts?.

The cache

The table is a fragment keyed on the relation — its rows, the newest updated_at among them and among everything recourse_includes names, the counts the rows draw, the viewer’s bookmarks and their time zone — so nothing has to expire it and a row written anywhere shows on the next request. A sorted, searched or filtered table is drawn live. A host that declared touch: true only to expire such a table can drop it.

On a phone

Below 768px the sidebar is a row of icons across the top, the trail and the search under it, and the table’s rows become stacked blocks, each cell labelled by its heading. A pair of arrows at the foot of the sidebar puts the words back beside every icon, and the choice is kept as a cookie so the server draws it that way from the first paint.
